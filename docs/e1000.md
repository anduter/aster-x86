# e1000 驱动：中断 + NAPI 式收包、TX 完成回收与统计

版本 0.71.0（2026-10-24）。本文描述 `src/kernel/dev/net/e1000.c` 在“纯轮询
TX/RX 环”基础上新增的三条主线，以及它们与 Linux `e1000` 驱动的对应关系。

| 文件 | 作用 |
| --- | --- |
| `src/kernel/dev/net/e1000.c` | 82540EM 驱动：IRQ、NAPI 轮询、TX 回收、watchdog、统计 |
| `src/kernel/dev/net/e1000.h` | 驱动 API 与 `e1000_stats_t` |
| `src/kernel/net/net.c` | 协议自检（语义未改），`net_init()` 末尾打印统计行 |
| `tools/e1000-probe.ps1` | 从 `serial-e1000.log` 断言驱动/网络日志 |

驱动**留在内核**，不搬 ring3；不新增 syscall（`include/abi.h` 未改），统计只通过
日志和 `e1000_stats_get()` 暴露给内核内部。

## 1. 初始化顺序与“延迟武装”

`core/bootseq.c` 的 `step_devices` 在 `step_interrupts` **之前**调用
`e1000_init()`，而 `interrupt_init()` 才做 `idt_init()` + `pic_remap()` +
注册 `irq0`。因此：

- `e1000_init()` 只做 `irq_register(line, ...)`，**不**直接 `irq_unmask()`；
  否则 `pic_remap()` 会把屏蔽字整体重写，刚放开的线又被关掉，甚至在 IDT
  装好之前就可能投递中断。
- 武装条件：`irq_count(0) != 0`，即 PIT 已经真正进过一次中断（说明 IDT 与
  PIC 重映射都完成）。第一次 `e1000_napi_poll()` 看到该条件后：
  1. `ioapic_present() && apic_base() != 0` → `irq_migrate_to_ioapic(line, BSP)`；
  2. 否则 `irq_unmask(line)` 留在 8259 PIC；
  3. 写 `IMS` 打开 RX 中断源，打印 `net: e1000 irq armed (...)`。
- IRQ 不可用（PCI `0x3C` 为 0/`0xFF`、线号 ≥16、或与 `1/4/12` 等系统 IRQ
  冲突、`irq_register()` 失败）时打印
  `net: e1000 irq unavailable, fallback polling`，保持纯轮询，不 panic。
- `e1000_init()` 里读 PCI 配置空间 `0x3C`（Interrupt Line，SeaBIOS 按 PIRQ
  路由写入；QEMU 通常为 11）。

武装日志（实测）：

```text
net: e1000 irq line=11 registered (arm deferred until irq0 fires)
...
ioapic: irq11 -> apic 0 vector=0x2b (PIC masked, LAPIC EOI)
net: e1000 irq armed (ioapic line=11)
net: e1000 irq: first interrupt icr=00000083, napi scheduled
```

## 2. 中断 + NAPI 式收包

### 2.1 硬中断（只做最小工作）

`e1000_irq_handler()`：

1. 读 `ICR`（读即清中断原因）；
2. `interrupts++`；
3. 写 `IMC = RX_INT_MASK` 屏蔽 RX 中断源（LSC/RXSEQ/RXDMT0/RXO/RXT0）；
4. `napi_scheduled = 1`；
5. 返回。

不在硬中断里搬包、不回收 TX、不重新武装，避免长中断上下文。

### 2.2 软轮询 `e1000_napi_poll(budget)`

- 预算 `E1000_NAPI_BUDGET = 8`（与 RX 环、软队列深度一致）；
- 每次调用：尝试武装 IRQ → `polls++` → 若有在途 TX 则回收 + watchdog →
  最多处理 `budget` 个 RX 描述符；
- 每个描述符：检查 `DD`，按 `errors` 记 `rx_errors`，把帧复制进 8 帧深度的
  软件队列（本 OS 没有 `napi_gro_receive`/协议栈回调，队列是“交付点”），
  清 `DD`，写 `RDT` 把描述符还给硬件；
- 软队列满时丢新帧并记 `rx_dropped`，但描述符照常归还，防止硬件停摆；
- 预算用尽且环里仍有 `DD` 帧时 `napi_budget_hits++`；
- 结束时若 `napi_scheduled` 置位：清标志、读 `ICR` 清挂起原因、
  写 `IMS = RX_INT_MASK` 重新打开 RX 中断（重新武装）。

### 2.3 兼容旧轮询接口

`e1000_rx_poll(buf, max_len)` 保留原语义（收到一帧返回长度，没有返回 0）：
软队列非空直接取一帧；为空则先跑一次 `e1000_napi_poll(8)` 再取。于是
`net.c` / `net_boot.c` 的 DHCP/DNS/ping/TCP 轮询路径**完全不用改**，
协议语义不变。

### 2.4 中断源

只开 RX 相关：`LSC | RXSEQ | RXDMT0 | RXO | RXT0`。不使用 `TXDW`
（发送完成中断）：TX 回收在轮询点做，避免每次发送都进中断。`RDTR = 0`，
不使用收包定时器。

## 3. TX 完成回收

旧实现只有一个共享发送缓冲，发送后原地自旋等 `DD`。新实现：

- 8 个描述符各自有独立 2KB 缓冲（`TX_BUF_SIZE`，pmm 连续 4 页），
  等价于 Linux 的 `skb` 生命周期：交给硬件后缓冲不能被复用；
- `tx_tail` = 下一个交给硬件的槽位（写 `TDT`），
  `tx_head` = 最老的未回收描述符；
- `e1000_send_frame()` 只做：取槽位、拷贝、写描述符（`EOP|IFCS|RS`）、
  推进 `TDT`、计数，**立即返回**（不再自旋）；
- 环满（`(tx_tail+1)%8 == tx_head`）时先回收一轮，仍满则丢弃并
  `tx_errors++`；
- `e1000_tx_reclaim()` 在 NAPI 轮询点回收：以 `DD` 为主判据（硬件读完并
  回写），并用 `TDH` 兜底（`TDH` 已越过的描述符视为已被硬件取走，与旧驱动
  “`TDH==TDT` 视为完成”的判据一致）；回收后打印一次
  `net: e1000 tx reclaim ok (freed=N)`；
- 回收计数累计到 `tx_reclaim`。

## 4. TX watchdog

- 记录“在途帧开始积压”的 tick（`tx_stall_since`），不是“最后一次发送”；
- `pending = (tx_tail - tx_head) mod 8`；`pending == 0` 清零计时；
- `timer_ticks() == 0`（boot 期，中断还没开）不做判断；
- 连续积压超过 `E1000_TX_WATCHDOG_TICKS = 200` tick（100Hz ⇒ 2s）：
  打印 `net: e1000 tx watchdog reset`，执行 `CTRL.RST` 软复位，重建
  TX/RX 环、恢复 `TCTL/TIPG/RCTL` 与中断使能，`resets++`，
  把未完成帧计入 `tx_errors`；
- 检查点挂在 NAPI 调用点（每次 `e1000_rx_poll`/`e1000_napi_poll`），
  **不新增全局定时器基础设施**。

## 5. 统计（ethtool 式）

`e1000_stats_get()` 返回 `e1000_stats_t`；`net_init()` 末尾打印一行：

```text
net: e1000 stats rx=10 tx=11 irq=0 polls=4183620 drop=0 reset=0 \
rx_bytes=1793 tx_bytes=1277 rx_err=0 tx_err=0 reclaim=11 budget_hits=0
```

| 字段 | 含义 |
| --- | --- |
| `tx_packets` | 成功交给硬件的帧数 |
| `tx_bytes` | 交给硬件的字节数（补零到 60 字节后的长度） |
| `tx_errors` | 环满丢弃 + watchdog 复位时未完成帧 |
| `tx_reclaim` | 累计回收的 TX 描述符数 |
| `rx_packets` | 交付到软队列的帧数 |
| `rx_bytes` | 交付字节数 |
| `rx_dropped` | 软队列满丢弃的帧数 |
| `rx_errors` | 描述符 `errors` 位 + 超长帧 |
| `interrupts` | 硬中断次数 |
| `polls` | `e1000_napi_poll()` 调用次数（本 OS 的收包是拉模式，数值很大） |
| `napi_budget_hits` | 预算用尽且仍有待处理帧的次数 |
| `resets` | watchdog 软复位次数 |

说明：`net_init()` 早于“延迟武装”，所以这一行的 `irq=` 在启动期通常为 0；
中断真正生效后的证据是 `net: e1000 irq armed` 与
`net: e1000 irq: first interrupt ...` 两行。

## 6. 与 Linux e1000 的对应关系

| Linux `e1000` | 本驱动 |
| --- | --- |
| `e1000_intr()`：读 ICR、关中断、`napi_schedule()` | `e1000_irq_handler()`：读 ICR、`IMC` 屏蔽 RX、置 `napi_scheduled` |
| `e1000_clean()` / `e1000_clean_rx_irq()`，NAPI budget | `e1000_napi_poll(budget=8)` + 8 帧软队列 |
| `e1000_clean_tx_irq()` 按 `DD` 回收 `skb` | `e1000_tx_reclaim()` + 每描述符固定缓冲 |
| `e1000_watchdog()`（定时器） | `e1000_tx_watchdog_locked()` 挂在 NAPI 调用点，200 tick |
| `e1000_reset()` / `e1000_down/up` | `e1000_reset_locked()`：`CTRL.RST` + 重建环 |
| `ethtool -S` 统计 | `e1000_stats_t` + 一行启动日志 |
| MSI/MSI-X、多队列、TSO、RSS、checksum offload | 未实现（见第 7 节） |
| `request_irq()`、`free_irq()` | `irq_register()` + `irq_migrate_to_ioapic()`/`irq_unmask()` |

## 7. 已知限制

- **无 MSI/MSI-X**：只用传统 INTx（QEMU 下 PCI `0x3C` = 11）。PCI 能力链
  里即使有 MSI 也未启用。
- **无多队列**：单 TX 环 / 单 RX 环，8 个描述符，单消费者。
- **无 TSO / 无 checksum offload**：协议栈自己算校验和，驱动只做
  `EOP|IFCS|RS`。
- **INTx 走 IOAPIC 边沿触发**：`irq_migrate_to_ioapic()` 使用 edge 配置
  （与仓库现有 IRQ12/IRQ1 迁移一致）。NAPI 屏蔽 RX 中断期间电平线保持
  低电平，重新开中断依赖新包的边沿；极端情况下可能少一次中断，但
  `e1000_rx_poll()` 的拉模式仍能取到包。
- **TX 回收只在轮询点做**：不启用 `TXDW`；如果系统长时间不做任何网络
  调用，已完成描述符要等下一次 NAPI 轮询才回收（环 8 个，通常足够）。
- **软队列深度固定 8**：突发超过 8 帧会丢新帧（`rx_dropped++`），不阻塞
  描述符归还。
- **polls 计数语义**：本 OS 的收包是“协议栈主动拉”，`polls` 等于
  `e1000_napi_poll()` 的调用次数，启动自检的紧循环会把它推到数百万；
  它不是 Linux 那种“中断触发的 NAPI 调度次数”。
- **延迟武装**：`e1000_init()` 不直接 `irq_unmask()`（见第 1 节），
  因此启动日志里 `net: e1000 irq line=... registered` 之后要等第一个
  tick 之后的第一次网络调用才会看到 `irq armed`。

## 8. 验证

```powershell
# 跑一次完整回归（98 项）并用日志断言驱动/网络行
powershell -File tools/e1000-probe.ps1

# 只分析现有日志
powershell -File tools/e1000-probe.ps1 -ReuseLog
powershell -File tools/e1000-probe.ps1 -ReuseLog -Log serial-a.log
```

必须出现的行：

- `net: e1000 irq ...`（注册；INTx 不可用时为
  `net: e1000 irq unavailable, fallback polling`）
- `net: e1000 napi budget=8 ...`
- `net: e1000 tx reclaim ok (freed=N)`
- `net: e1000 stats rx=.. tx=.. irq=.. polls=.. drop=.. reset=..`
- 既有协议自检：`net: ARP reply`、`net: ICMP echo reply`、
  `net: UDP echo reply`、`net: TCP echo reply`、`net: dhcp ok`、
  `net: dns ok`、`net: ping ok`

## 9. 构建注意（增量构建的已知坑）

`src/kernel/user/user_blob.asm` 用 `incbin` 嵌入 `user_shell.elf`，而
`build.ps1` 的 `.asm` 增量判断只看 `.asm`/头文件，不看 `user_shell.elf`。
如果两次构建之间 shell ELF 内容变了，会嵌入旧 blob，导致启动时
`trust: shell signature INVALID` 并 panic。修复（不改 `build.ps1` 的前提下）：

```powershell
Remove-Item .obj-<name>\user\user_blob.o -Force
```

再重新构建即可。
