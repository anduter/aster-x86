## 4. 安装 / 运行（QEMU）

需求：QEMU 11.x（x86_64），支持 `-kernel`/PVH；无需安装 Aster 到磁盘。

### 4.1 交互运行（推荐）

在发布目录内：

```text
qemu-system-x86_64 -kernel aster-ng.elf -m 256 -cpu max -vga std ^
  -drive file=disk.img,format=raw,if=ide -serial stdio -display gtk
```

- `-vga std`：1280×800×32 framebuffer（display server 的像素断言前提）；
- `-serial stdio`：内核/用户态串口证据（与 QEMU monitor 抢占同一终端，按
  `Ctrl+Alt+2` 切 monitor，`Ctrl+Alt+1` 回来）；
- 启动后应看到 WM 面板、`/bin/demo` 窗口；串口包含
  `ng: ring3 hello`、`ng: shell ready`、`ng: WP3-3 selftest PASS`。
- shell 是 L3 用户程序；`help` / `ls` / `cat` / `dmesg` / `pkg list` /
  `spawn /bin/proc hello` / `exit` 可用。

### 4.2 无 GUI 串口冒烟

```text
qemu-system-x86_64 -kernel aster-ng.elf -m 256 -cpu max -vga std ^
  -drive file=disk.img,format=raw,if=ide -display none ^
  -serial file:serial.log -no-reboot
```

等待 8–15 秒后结束 QEMU，检查 `serial.log` 的 `PASS` / `PANIC` 行。
`-vga none` 会走 VGA 文本回退（无 framebuffer，display/WM 自检跳过或降级）。

### 4.3 其它 CPU

```text
qemu-system-x86_64 -kernel aster-ng.elf -m 256 -cpu qemu64 -vga std ^
  -drive file=disk.img,format=raw,if=ide -serial stdio -display gtk
```

`qemu64` 不启用 SMEP/SMAP；E3 门禁在两种 CPU 下都跑过。

## 5. 校验

### 5.1 SHA-256

PowerShell（在发布目录内）：

```powershell
$bad = 0
Get-Content SHA256SUMS | ForEach-Object {
    $h, $p = $_ -split '  ', 2
    $a = (Get-FileHash -Algorithm SHA256 -LiteralPath $p).Hash.ToLowerInvariant()
    if ($a -ne $h) { Write-Host "MISMATCH $p"; $bad++ }
}
if ($bad -eq 0) { 'SHA256SUMS: PASS' } else { throw "$bad mismatches" }
```

Linux/WSL/Git Bash：

```bash
sha256sum -c SHA256SUMS
```

### 5.2 ABI 冻结

在仓库根（需要 `src/` 与 `sdk/` 的完整树）：

```powershell
powershell -File tools/abi-check.ps1
```

所以应在仓库树上跑，而不是在发布目录里跑。

## 6. 已知限制（D0）

1. **WM 死循环无法救活**：`src/ng/thread.h` 的调度是协作式（只在
   `sched_yield/thread_sleep/thread_exit` 切换），WM 在 ring3 自旋后整机冻结，
   sessiond 无法检测/重启。S1 的“杀 WM/杀应用/杀 sessiond”三场景 PASS；
   “WM 卡死”记 KNOWN。修复需内核抢占/watchdog（D1 前）。
2. **用户态 #PF/#GP 仍 panic**：syscall 内的用户指针由 uaccess 校验并返回
   `EFAULT`；应用直接解引用坏地址或执行特权指令会进 `panic`。ABI 1.0 不承诺
   用户 fault 隔离（`abi-1.0.md` §10 第 7 项）。
3. **sessiond 无接管**：杀 sessiond 后 displayd/WM/应用成孤儿继续跑，注册表与
   重启策略消失（architecture 开放决策 2；WP3-5 场景 c 如实记录）。
4. **权限模型 root-only**：所有进程 uid=0；ticket 是 bearer token，无 cap/
   revoke/防伪；知道 ticket 的进程可发消息，知道 shm handle 的进程可映射。
5. **无安装器/包启动**：SDK 示例进镜像仍靠构建期 `.incbin`；`-SdkDemo` 是
   demo harness，不是产品部署机制；`pkg install` 未实现。
6. **静态 ELF64 / 无 POSIX**：无动态链接、`mmap`/`mprotect`/`lseek`/`dup`/
   `pipe`/`socket`/`sleep`；POSIX Profile 属 D1。
7. **QEMU 矩阵有限**：stdvga 1280×800×32 + PIIX3 IDE + PS/2 键盘；鼠标/IME/
   真机/其它显示控制器不在 D0。像素断言只在 QMP screendump 的 stdvga 下成立。
8. **ABI 1.0 延后项**：未分配号 `ENOSYS`、IPC 时间单位、cap、每进程 uid/fd、
   用户 fault 隔离、运行时 ABI 版本查询、`SHM_FREE`、结构体对齐校验等，见
   `abi/abi-1.0.md` §10。它们不阻塞 D0，但 D1 前要处理。
9. **外部开发者测试/1h smoke 未包含**：见 §1 的说明。

## 7. 复现构建

仓库根：

```powershell
# 一条命令：ABI 门禁 + build-ng + 发布目录 + SHA256 自检
powershell -File tools/release-ng.ps1

# 只复用已有 dist-ng 产物（不重新编译）
powershell -File tools/release-ng.ps1 -SkipBuild

# 只跑构建
powershell -File tools/build-ng.ps1
```

工具链：

- clang 23.1.4 / ld.lld 23.1.4（`D:\msys64\mingw64\bin`）；
- 内核 target `x86_64-elf`，`-ffreestanding -nostdlib -mno-red-zone
  -fno-stack-protector -mno-sse -mgeneral-regs-only`；
- 用户 ELF：静态 `ET_EXEC`/`EM_X86_64`，基址 `0x40000000`；
- QEMU 11.0.0。

发布脚本只做本地文件；不会 `git push`、不会创建远端 release、不会打 tag、
不会签名。
