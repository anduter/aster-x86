## 10. 偶发 #PF 根因修正（21:20）

之前把 user: exception 14 at eip=0x4000415c err=15 当作“PTE 保留位”问题，**结论已修正**：

1. **0x4000415c 是预期输出**：i686-elf-nm 显示它是 user_shell.elf 的 odata_ret，即 sectest 的 rodata NX 取指测试目标；err 按 %x 打印，15 = x15 = P|U|I/D（NX 取指），正常启动每次都有。
2. **真正根因：SMP 僵尸回收竞态**。proc_exit 先发布 ZOMBIE 并唤醒父进程，之后才切走；父进程可能在另一颗 CPU 上立刻 proc_reap，释放退出线程**仍在使用的 64KB 内核栈**并销毁该 CPU 正用作 CR3 的页目录。表现为偶发跳到 x0/0x18 取指（err=0x11, cr2==eip），随后 shell 被杀、reexec 哨兵超时。
3. **修复**（提交 7496661）：
   - proc/process.c：每 CPU 静态“退出栈”；proc_exit 在自己栈上关 fd/释放 cap 后 cli 切到退出栈，proc_exit_finish **先把 TSS.esp0/current/CR3 交给下一个进程，再** dequeue + 置 ZOMBIE + 唤醒 wait；
   - proc/switch.asm：新增 proc_exit_on_stack；
   - 顺带修 proc_fork 的 mm_clone_user_pages 失败回滚（FILE→s_close_ex、PIPE_W→pipe_unref_write、cap_release_all、
ative_proc_free）。
